# NYXORA — Contract Privacy Gateway Roadmap & Architecture

> **Pitch:** Strong AI on your most sensitive documents, without the documents ever leaving your control.  
> **Context:** MAKERS² 2026 (Track 02: AI for Work & Business). Privacy gateway sitting between company users and external frontier AI models.

---

## 1. Non-Negotiable Privacy & Security Invariants

1. **Send Gate enforcement:** External AI providers must only ever receive approved, masked text (`[PERSON_7f3a9b]`, `[COMPANY_3c91a2]`, etc.)—enforced in backend code, never trusted to the frontend.
2. **No plaintext secrets or raw PII at rest:**
   - Passwords hashed with Argon2id (`backend/app/security.py`).
   - Auth tokens stored as SHA-256 hashes (`auth_sessions`).
   - Provider API keys configured by the Owner are Fernet-encrypted at rest (`provider_configs`) and never returned in plaintext (masked hints like `••••a9f2` only).
   - Audit logs (`audit_logs`) store metadata only (user, session ID, action, provider, entity counts, timestamps)—never raw text, prompts, or vault mappings.
3. **Never claim legal compliance:** Position NYXORA as reducing personal-data exposure and keeping a human in control, not as legal certification (Law 18-07 / 25-11 context).

---

## 2. Locked-In Architecture Decisions

### Roles (`owner` vs `user`)
- **`owner`:** Manages workspace settings—encrypted provider API keys, enabled models & defaults, rulebook prompt & custom rules (`/rules`), user provisioning (`POST /auth/users`), metadata-only audit log (`/audit`), and evaluation metrics (`/metrics`).
- **`user`:** Clean ChatGPT/Claude-style experience at `/chat` only. `/rules`, `/metrics`, and all technical settings are hidden. Picks from Owner-enabled models (+ thinking effort) and chats using `manual` or `auto` review mode.

### Model Discovery & Provider Adapter
- `GET /providers/models` returns Owner-enabled models (discovered live via provider `/models` endpoints or curated fallback) plus supported parameters (`supports_thinking`, `thinking_efforts`) and workspace defaults.
- All frontier providers sit behind one interface: `send(masked_messages, model, thinking_effort) -> text`.

### Layered Filtering Pipeline (Text-First MVP)
Each new message passes sequentially through pluggable layers:
1. **Pass 0 — Vault Lookup (`<1ms`):** Deterministically replaces any entity already in the session vault (`James` → `[PERSON_7f3a9b]`) so placeholders stay consistent across the entire conversation.
2. **Layer 1 — Rules & Presidio NER (CPU):** Regex patterns, company custom rules (`custom_rules`), and Microsoft Presidio + spaCy (`en_core_web_lg`), mapping entities to NYXORA's unified types (`PERSON`, `COMPANY`, `EMAIL`, `PHONE`, `ADDRESS`, `ID`, `BANK`, `CUSTOM`). Skip Presidio's built-in anonymizer so placeholder formatting stays unified.
3. **Layer 2/3 — Local Rulebook SLM (Separate GPU Server over OpenAI-compatible HTTP, optional/post-MVP):** Extraction-only (`httpx` → `/v1/chat/completions`) returning strict JSON lists of missed verbatim strings (never rewriting text, never returning offsets).
   - **SLM Latency Optimizations:** Pre-mask with Pass 0 + Layer 1 first; skip short/trivial follow-ups with no entities/numbers; run ~400-word chunks concurrently (`httpx.AsyncClient` + `asyncio.Semaphore`) to leverage vLLM continuous batching; enforce guided JSON schema + `temperature=0` + `max_tokens=256`; use a quantized non-thinking 3B–7B model (`Qwen2.5-7B-Instruct-AWQ` or `Phi-3.5-mini`) with vLLM `--enable-prefix-caching` and `--max-model-len 2048`.

### Placeholders, Review Gate & Non-Streaming Responses
- **Random-ID Placeholders (`[TYPE_<6-hex>]`):** Use random hex suffixes (e.g., `[PERSON_7f3a9b]`) generated by `VaultData` instead of sequential `_1` counters to avoid count leakage and collisions. Keep brackets so cloud LLMs preserve tokens verbatim.
- **Accept / Reject Gate (`manual` vs `auto`):**
  - **`manual` (Manual Approval):** `POST /sessions/{id}/messages` returns findings and masked preview (`needs_review`). User chooses **Accept (Approve & Send)** or **Reject (Deny)**—**no** conversational AI re-masking or stop-and-edit loop in MVP (deferred to v2).
  - **`auto` (Auto Review):** Commits vault mappings and dispatches through the Send Gate automatically without pausing.
- **Non-streaming MVP + Deterministic Unmasking:** Return the full masked reply from the cloud provider, then unmask once via `VaultData.unmask_text()` (longest-match, case-insensitive regex, `<1ms`, zero LLM cost). Bracket-aware SSE streaming is deferred to v2 so split `[PERSON_` chunks never flash unmasked/raw fragments.

### Persistent Multi-Week Sessions & Long Context (100+ Messages)
- **Persistent encrypted vault:** Persist the Fernet-encrypted vault blob in SQLite/Postgres alongside `MaskedMessage` (with Redis as fast hot cache) so users can reopen chats weeks later and still view unmasked text. Clicking **End & Wipe Vault** (`DELETE /sessions/{id}`) deletes both immediately. *(Keep an `EPHEMERAL_VAULTS_ONLY` env flag for strict zero-disk deployments.)*
- **Long-context efficiency:** Never re-filter message history `#1..#99` (it is already stored masked). Filter **only** the newest message (`#100`), pre-applying Pass 0 Vault Lookup first. Window/summarize already-masked history when calling the external provider.
